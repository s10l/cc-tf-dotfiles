# Repository layout

Two shapes share one layout: **single-device** (one entry YAML) and
**multi-device** (one entry YAML per device, everything else shared). The
multi-device shape is the general case; a single-device repo simply has one
entry and one release branch.

```
<repo>/
  esphome/                          firmware configs only
    <device>.yaml                   entry point, one per device
    <device>.package.yaml           that device's composition
    screenshot.yaml                 UI preview config (OPTIONAL: LVGL only)
    common/
      hardware.yaml                 board/peripherals
      ota.yaml                      ota, declared ONCE
      webserver.yaml                web_server (recovery path)
      debug.yaml                    restart/diagnostic entities
      substitutions.yaml            shared $values
      screens.yaml, fonts.yaml      OPTIONAL: LVGL UI
    secrets.yaml                    DUMMY placeholders only (committed)
  homeassistant/                    OPTIONAL: HA-side deliverables
    packages.d/
      <pkg>.yaml                    package root (mapping of domain keys)
      <pkg>.d/
        ports.yaml                  input_text ports (foreign ids live here)
        helpers.yaml                package-owned helpers
        template.yaml               mirrors/derived values
        automation.yaml             control loop
        CONTRACT.md                 port table
    wiring.d/
      wiring.<pkg>.live.yaml        real bindings
      wiring.<pkg>.bench.yaml       offline bindings (never with live)
  .gitlab/
    merge_request_templates/Default.md
  .gitlab-ci.yml                    matrix build + release installs
  Makefile                          DEVICES-driven targets
  makefile.conf                     local settings (seeded by make configure)
  secret_refs.yaml                  !secret name -> reference URI (never values)
  check-secrets.sh                  dummy-placeholder guard
  prepare-secrets.sh                HUMAN-ONLY: secrets.yaml -> import JSON + refs
  secrets.tmp.json                  GENERATED, gitignored: real values until imported
  check-package-isolation.sh        OPTIONAL: HA isolation lint
  deploy-ha.sh                      OPTIONAL: HA copy-in
  esphome.sh                        committed builder CLI (paired)
  AGENTS.md, README.md, LICENSE
```

## What belongs where

| Path | Rule |
|---|---|
| `esphome/` | Only firmware inputs. Anything here can trigger a compile; anything outside does not. |
| `homeassistant/` | Only HA packages/wiring. Never imported by firmware. |
| `*.yaml` at the `esphome/` root | Device entry, its `<device>.package.yaml`, or the screenshot entry. Shared files belong under `esphome/common/` so a bundle can exclude every other root YAML. |
| `secret_refs.yaml` | Reference URIs only. A value here is a bug. |
| `esphome/secrets.yaml` | Dummy placeholders only, committed on purpose, excluded from every bundle. |
| `prepare-secrets.sh` | Human-only helper behind `make prepare-secrets`. Agents must not run it. |
| `secrets.tmp.json` | Generated by `make prepare-secrets`, gitignored, holds real values until imported - never commit, never let an agent read it. |
| `build/` | Generated. Never committed. |
| `esphome.sh` | Committed on purpose; the builder CLI is part of the deploy contract. |

## Naming contract

The only thing that separates devices is one unbroken chain:

```
entry file stem == esphome: name: == bundle file stem == CI/Make CFG
```

With no OTA host in `common/ota.yaml`, the compiled config's `esphome name:`
is the OTA target. A correct bundle filename plus a wrong `name:` still
flashes the wrong device. Enforce it:

- Makefile bundle rule asserts the entry declares `name: <stem>`.
- CI `.builder` pack step asserts the same and checks the archive root.
- `install-*` asserts it runs on its own `release-<device>` branch.

## Single-device vs multi-device

| Concern | Single-device | Multi-device |
|---|---|---|
| `DEVICES` (Makefile) | one name | space-separated list |
| Entry/package YAMLs | one pair | one pair per device |
| Release branches | `release-<device>` | one per device |
| `make validate` | device argument optional | device argument required |
| CI matrix | one entry | one entry per device |
| Release MR build | `build-<device>` | `build-<device>` per device |

A second device is added by: creating its entry/package pair, adding it to
`DEVICES`, adding its name to the CI matrices, and duplicating the
`build-`/`install-` block with its own `release-<device>` branch.

## Optional parts

- **No display/LVGL**: omit `screenshot.yaml`, the `screenshot*` targets, the
  `SCREENSHOT_*` variables, and the screenshot line in the MR template.
- **No Home Assistant**: omit `homeassistant/`, `deploy-ha.sh`,
  `check-package-isolation.sh`, the `homeassistant` target and the
  `ha-isolation` CI job.
- **No bundle mode**: `USE_BUNDLE=0` sends the plain entry YAML; the config
  must then fetch its parts through a git `remote_base` package instead of
  `!include` (needs `gluser`/`glpat` secret refs).
